01

What This Module Does

Installs a standalone, max-feature sqlite3 binary to /system/bin/sqlite3. Built from source with the Android NDK. Every stable feature enabled, tuned for stability and maximum compatibility.

Replaces stock sqlite3 shell
Does not touch libsqlite.so
Apps unaffected
Safe to uninstall
🛡
Safe by design. Only the interactive sqlite3 shell is replaced. libsqlite.so used by Android framework and all apps is untouched.
🆕
New in this release. SQLITE_SECURE_DELETE was accidentally enabled in every earlier build — the flag is tested with #ifdef, so =0 switched it on and every DELETE zero-filled its freed pages. It is now gone, along with two flags that stopped existing in SQLite years ago (ENABLE_JSON1, ENABLE_DESERIALIZE). The parallel sorter is enabled, backup uses SQLite's online backup API instead of cp, every helper command sets a busy timeout, and build.sh now reads the compile options back out of the finished binary and refuses to ship a build that does not match.
⚙
Wrapper architecture. The installed sqlite3 is a lightweight shell script that detects your device RAM, sets an adaptive mmap_size, injects performance PRAGMAs via -cmd, then calls sqlite3.real — the actual compiled binary.

Compile Flags

⚙ Compiler
-O2Balanced optimization. Safe and stable — no aggressive transformations that risk miscompilation on Android.
-march=armv8-aTargets the ARMv8-A baseline. Compatible with every arm64 Android device regardless of chip generation.
-fPIEPosition-Independent Executable. Required by Android for ASLR (address space layout randomization).
-pieLinker flag that pairs with -fPIE. Android 21+ refuses to run non-PIE executables.
-fuse-ld=lldUses LLVM's LLD linker. Better dead-code elimination and required for correct LTO support with NDK.
-fomit-frame-pointerFrees the frame pointer register for general use. Slight speed and size gain. Safe for a CLI tool.
-fvisibility=hiddenMarks all symbols as internal by default. Reduces binary size and prevents symbol leakage.
-ffunction-sectionsPuts each function in its own ELF section so the linker can discard unused ones via --gc-sections.
-fdata-sectionsSame as above but for data objects. Works together with -ffunction-sections.
-fstack-protector-strongStack smashing protection on functions that use buffers. Stability and security without the overhead of full stack protection.
🔗 Linker
-Wl,--gc-sectionsGarbage-collects ELF sections with no references. Works with -ffunction-sections / -fdata-sections.
-Wl,--strip-allStrips all symbol and debug info from the final binary. Smaller size, nothing useful for reverse engineering.
-Wl,-O2Linker-level optimization pass. Merges identical sections and tightens the output layout.
-Wl,--build-id=noneRemoves the GNU build-ID note section. Shaves bytes with no practical downside for a Magisk module.
-Wl,-z,max-page-size=16384Required for Android 15+ devices with 16 KB memory pages. Without it the binary may segfault on load.
-ldlLinks the dynamic linker library. SQLite shell uses dlopen internally even with extension loading disabled.
-lmLinks the math library. Required by SQLite math functions.
-llogLinks Android's logging library. Needed for correct integration with the Android runtime environment.
🗄 Core
-DSQLITE_THREADSAFE=1Full mutex serialization. Multiple threads can safely share a single database connection.
-DSQLITE_USE_URI=1Enables URI filenames: file:db?mode=ro&cache=shared. Required for read-only opens and shared-cache mode.
-DSQLITE_OMIT_LOAD_EXTENSIONDisables runtime loading of .so extension files. Reduces attack surface on Android.
-DSQLITE_SECURE_DELETE=0 removedSQLite tests this flag with #ifdef, not by value — =0 still defined it and therefore enabled secure delete, zero-filling every freed page. Builds up to v3.53.4 shipped with it on by mistake. Omitting the flag is what actually turns the feature off. Use PRAGMA secure_delete=ON per connection if you want it.
-DSQLITE_DQS=0Disables legacy double-quoted string literals. Enforces correct SQL: double-quotes are identifiers, single-quotes are strings.
-DSQLITE_LIKE_DOESNT_MATCH_BLOBSLIKE skips BLOB columns instead of attempting string coercion. More correct behavior and a small speedup.
-DSQLITE_HAVE_ISNANUse the platform isnan() from <math.h> instead of SQLite's own fallback. Correct NaN handling on Android.
-DHAVE_USLEEP=1Enables microsecond-precision sleep for lock retry loops. Essential for correct busy-timeout behavior.
-DHAVE_MALLOC_USABLE_SIZE=1Lets SQLite ask bionic for the true size of an allocation instead of tracking it itself. Slightly less per-allocation overhead.
⚡ Performance & Memory
-DSQLITE_TEMP_STORE=2Temporary tables and indices default to RAM, but PRAGMA temp_store can still override it. Was =3, which forced memory unconditionally and could push the process into OOM on a large temp table.
-DSQLITE_DEFAULT_MEMSTATUS=0Disables per-allocation memory accounting. Removes overhead from every malloc/free call.
-DSQLITE_MAX_WORKER_THREADS=4Upper bound for the parallel sorter. Was implicitly 0, which disabled parallel sorting entirely.
-DSQLITE_DEFAULT_WORKER_THREADS=2Two sorter threads by default — noticeably faster CREATE INDEX and large ORDER BY on a multi-core phone.
-DSQLITE_ENABLE_SORTER_REFERENCESThe sorter keeps rowid references instead of whole rows where it can, cutting memory use when sorting wide tables.
-DSQLITE_DEFAULT_CACHE_SIZE=-16000Compile-time default page cache ~16MB. Overridden at runtime to -20000 by the session wrapper.
-DSQLITE_STMTJRNL_SPILL=-1Statement journals never spill to disk — always stay in RAM.
-DSQLITE_DEFAULT_WAL_SYNCHRONOUS=1WAL-mode sync defaults to NORMAL. Faster on flash without sacrificing safety.
-DSQLITE_DEFAULT_SYNCHRONOUS=1Default journal-mode sync is NORMAL. Balance between data safety and write speed.
-DSQLITE_DEFAULT_FOREIGN_KEYS=1FK enforcement ON by default. No need to run PRAGMA foreign_keys=ON every session.
-DSQLITE_DEFAULT_MMAP_SIZE=268435456Compile-time mmap default 256MB. Overridden at runtime by adaptive RAM detection in wrapper.
-DSQLITE_MAX_MMAP_SIZE=1099511627776Maximum allowed mmap window 1TB. Removes the ceiling for very large databases.
🔍 Full-Text Search
-DSQLITE_ENABLE_FTS3_PARENTHESISExtends FTS3/FTS4 query syntax to support parenthesized boolean expressions: word1 AND (word2 OR word3).
-DSQLITE_ENABLE_FTS4Full-Text Search v4. Automatically includes FTS3. Required to read Android system DBs (contacts, calendar, SMS).
-DSQLITE_ENABLE_FTS5Full-Text Search v5. Completely independent engine from FTS4. Faster ranking, BM25 scoring, prefix queries, highlight/snippet.
🌐 JSON · 📍 Geospatial · 📊 Stats & Math
-DSQLITE_ENABLE_JSON1 removedThis macro no longer exists anywhere in the SQLite source. JSON has been built in since 3.38, so the flag did nothing and sqlite_compileoption_used('ENABLE_JSON1') returned 0 — which looked like a broken build. Every JSON function is still available.
-DSQLITE_ENABLE_RTREER-Tree spatial indexing. Fast bounding-box queries on coordinate data.
-DSQLITE_ENABLE_GEOPOLYPolygon-based geospatial extension on top of R-Tree. Containment and overlap queries on arbitrary polygons.
-DSQLITE_ENABLE_STAT4Histogram statistics on index columns during ANALYZE. Better query planner decisions.
-DSQLITE_ENABLE_MATH_FUNCTIONSAdds sin(), cos(), sqrt(), pow(), log(), floor(), ceil(), pi() directly in SQL.
-DSQLITE_ENABLE_PERCENTILEAdds percentile(), percentile_cont(), percentile_disc() aggregate functions.
-DSQLITE_ENABLE_OFFSET_SQL_FUNCEnables sqlite_offset(column) — returns byte offset of a column value in the DB file.
↻ Session · 🔬 Virtual Tables · 🔧 Developer
-DSQLITE_ENABLE_SESSIONRecord DB changes as a changeset blob, apply to another database. Enables sync workflows.
-DSQLITE_ENABLE_PREUPDATE_HOOKFires before every UPDATE/DELETE with old row values. Mandatory dependency for SESSION.
-DSQLITE_ENABLE_DESERIALIZE removedAlso no longer a real macro. Deserialize is on by default since 3.36 and is switched off with SQLITE_OMIT_DESERIALIZE, which this build does not use. sqlite3_deserialize() works exactly as before.
-DSQLITE_ENABLE_SNAPSHOTOpen a read transaction against a specific historical WAL snapshot — consistent multi-step reads while writers keep going.
-DSQLITE_ENABLE_RBUResumable Bulk Update: apply a large update to a live database in interruptible chunks without holding a long write lock.
-DSQLITE_ENABLE_UNLOCK_NOTIFYUnlock-notification API. Threads waiting on a locked DB are notified instead of polling.
-DSQLITE_ENABLE_DBSTAT_VTABdbstat virtual table — page-level statistics of the database file.
-DSQLITE_ENABLE_DBPAGE_VTABdbpage virtual table — raw read/write access to every page of the DB file.
-DSQLITE_ENABLE_STMTVTABsqlite_stmt virtual table — lists all open prepared statements.
-DSQLITE_ENABLE_BYTECODE_VTABbytecode virtual table — exposes VDBE bytecode of a statement as rows.
-DSQLITE_ENABLE_CARRAYcarray virtual table — bind a C array to a virtual table for SQL joins.
-DSQLITE_ENABLE_COLUMN_METADATAEnables sqlite3_column_table_name() and related APIs for column origin info.
-DSQLITE_ENABLE_NORMALIZEEnables sqlite3_normalized_sql() — replaces all literals with ? for query logging.
-DSQLITE_ENABLE_UPDATE_DELETE_LIMITAdds LIMIT and ORDER BY to UPDATE and DELETE statements.
-DSQLITE_ENABLE_EXPLAIN_COMMENTSHuman-readable comments in EXPLAIN output. Makes VDBE opcode listing easier to read.
-DSQLITE_ENABLE_UNKNOWN_SQL_FUNCTIONSuppresses "no such function" in EXPLAIN mode. Plan queries with UDFs without executing them.
-DSQLITE_SOUNDEXAdds soundex() for phonetic string matching.
-DSQLITE_ENABLE_API_ARMORRuntime sanity checks on public API entry points. Catches NULL pointers, closed handles.
-DSQLITE_ENABLE_NULL_TRIMTrailing NULLs not stored in B-Tree records. Reduces row size for sparse tables.
-DSQLITE_ENABLE_STMT_SCANSTATUS opt-inPer-statement scan statistics, powering .scanstats. It adds counters to every sqlite3_step() call whether you use them or not, so it is off by default now. Rebuild with WITH_SCANSTATUS=1 ./build.sh to get it back.
💡
FTS3 / FTS4 / FTS5 are all included. FTS5 is a completely separate engine — no shared code with FTS4. FTS4 is kept because Android system databases use FTS4 tables. FTS3_PARENTHESIS is independent from both and extends FTS4 query syntax.

Session Config

The module uses a wrapper + real binary architecture. PRAGMAs are injected automatically via -cmd on every shell start — no .sqliterc dependency, no $HOME issues.

Auto-applied on every session start

✓
These are always active. You never need to type them manually.
cache_size-20000~20MB page cache in RAM. Overrides compile-time default of -16000.
temp_storeMEMORYTemp tables stay in RAM, not on flash.
busy_timeout5000Wait up to 5 seconds on a locked DB instead of failing immediately.
mmap_sizeadaptive64MB <3GB RAM · 128MB 3–6GB · 256MB >6GB. Detected at startup from /proc/meminfo.
synchronousNORMALBalanced speed/safety. Applied on interactive sessions only.
wal_autocheckpoint500Checkpoint WAL after ~2MB. Applied on interactive sessions only.
foreign_keysONFK enforcement. Applied on interactive sessions only.
recursive_triggersONTriggers can call themselves. Applied on interactive sessions only.
analysis_limit1000ANALYZE samples up to 1000 rows per index. Applied on interactive sessions only.

Full config file — manual use

Deployed to /data/local/.sqliterc-full. Use when you need the commented-out dangerous PRAGMAs for personal databases.

Load full config on a specific DB
sqlite3 -init /data/local/.sqliterc-full /data/local/tmp/mydb.db
⚠
Interactive vs DB session. When you open sqlite3 with a DB path, journal_mode, foreign_keys, and wal_autocheckpoint are intentionally NOT injected — system databases may reject them. Only safe PRAGMAs are applied.

Basic Usage

All commands require root. Run from Termux or any root shell or su -c command

Open shell (in-memory)
sqlite3
Open or create a DB file
sqlite3 /data/local/tmp/mydb.db
Open read-only (URI)
sqlite3 "file:/data/local/tmp/mydb.db?mode=ro"
Dot commands (CLI only — not SQL)
.open /data/local/tmp/other.db    -- switch to another DB without restarting
.tables                            -- list all tables
.schema users                      -- show CREATE statement for a table
.headers on                        -- show column names in output
.mode column                       -- aligned column output
.mode box                          -- box-drawing table output
.output /data/local/tmp/out.txt    -- redirect output to file
.output stdout                     -- restore output to screen
.read /data/local/tmp/script.sql   -- execute a SQL file
.dump                              -- dump entire DB as SQL
.quit                              -- exit the shell
Basic SQL
CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, age INTEGER);
INSERT INTO users VALUES (1, 'Alice', 30);
SELECT * FROM users WHERE age > 20;
WAL mode (recommended for personal DBs)
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA cache_size = -20000;
System databases
sqlite3 /data/data/com.android.providers.contacts/databases/contacts2.db
sqlite3 /data/data/com.android.providers.telephony/databases/mmssms.db

INSERT INTO docs VALUES('SQLite Guide', 'Fast embedded database engine');

CREATE VIRTUAL TABLE notes USING fts4(content);
INSERT INTO notes VALUES('hello world');
SELECT * FROM notes WHERE notes MATCH 'hello';
-- parenthesized boolean (FTS3_PARENTHESIS)
SELECT * FROM notes WHERE notes MATCH 'hello AND (world OR earth)';

sqldiff — Compare Databases

Compares two SQLite databases and outputs the SQL needed to transform one into the other. Useful for auditing changes, migrations and backups.

Basic usage
-- Show all SQL changes to transform db1 into db2
sqldiff db1.db db2.db

-- Only schema differences
sqldiff --schema db1.db db2.db

-- Only one specific table
sqldiff --table users db1.db db2.db

-- Summary only (no SQL output)
sqldiff --summary db1.db db2.db
Wrap in transaction
sqldiff --transaction db1.db db2.db | sqlite3 db1.db
💡
Backup workflow. Make a backup with sqlite3-tool backup, modify the original, then use sqldiff to see exactly what changed.

sqlite3-tool — Helper Commands

A convenience wrapper with 16 ready-to-use commands. No SQL knowledge required for common maintenance tasks. Every command sets a busy timeout first, so touching a live database waits instead of failing immediately with database is locked.

All commands
sqlite3-tool integrity    <db>           -- PRAGMA integrity_check
sqlite3-tool vacuum       <db>           -- defragment and shrink
sqlite3-tool analyze      <db>           -- update query planner stats
sqlite3-tool optimize     <db>           -- PRAGMA optimize
sqlite3-tool wal-checkpoint <db>         -- PRAGMA wal_checkpoint(FULL)
sqlite3-tool tables       <db>           -- list tables with row counts
sqlite3-tool indexes      <db>           -- list all indexes
sqlite3-tool schema       <db> [table]   -- show CREATE statements
sqlite3-tool size         <db>           -- page stats and file size
sqlite3-tool info         <db>           -- quick database summary
sqlite3-tool biggest      <db> [n]       -- largest objects on disk (dbstat)
sqlite3-tool backup       <db> <dest>    -- online backup, then verified
sqlite3-tool restore      <backup> <dest> -- restore from backup
sqlite3-tool doctor       <db>           -- run sqlite3-doctor
sqlite3-tool compile-options [filter]    -- how this sqlite3 was built
sqlite3-tool version                     -- tool and SQLite versions
Practical examples
-- Check and repair fragmentation
sqlite3-tool integrity /data/local/tmp/mydb.db
sqlite3-tool vacuum    /data/local/tmp/mydb.db

-- Safe backup before modifying a system DB
sqlite3-tool backup /data/data/com.example/databases/app.db /sdcard/app_backup.db

-- Quick overview of any database
sqlite3-tool info /data/local/tmp/mydb.db

-- List all tables with row counts
sqlite3-tool tables /data/local/tmp/mydb.db
🛡
Backup uses SQLite's online backup API (.backup), not a file copy. It is safe on a live database, needs no write access to the source, and the result is checked with integrity_check before the command reports success. Earlier versions ran wal_checkpoint(FULL) and then cp — that writes to the source and is not atomic, so a concurrent writer could produce a corrupt backup. Restore now deletes any stale -wal and -shm next to the destination instead of copying them across.

Verify After Install

Version
sqlite3 --version
sqlite3.real --version    -- verify real binary directly
Verify session PRAGMAs are active
-- run inside sqlite3 shell (no DB path)
PRAGMA cache_size;    -- -16000  (compile-time default)
PRAGMA busy_timeout;  -- 5000    (set by the wrapper)
PRAGMA temp_store;    -- 2       (memory, overridable)

-- NOTE: .open makes a NEW connection and resets busy_timeout and
-- mmap_size back to the compiled defaults. Pass the database on the
-- command line if you want the wrapper settings to apply to it.
Verify mmap (needs a real DB file)
sqlite3 /data/local/tmp/test.db
PRAGMA mmap_size;    -- 268435456 (or less on low-RAM devices)
.quit
rm -f /data/local/tmp/test.db
Test FTS5
sqlite3 /data/local/tmp/t.db "CREATE VIRTUAL TABLE t USING fts5(c); INSERT INTO t VALUES('hello world'); SELECT * FROM t WHERE t MATCH 'hello';"
Test FTS4
sqlite3 /data/local/tmp/t.db "CREATE VIRTUAL TABLE t4 USING fts4(c); INSERT INTO t4 VALUES('hello world'); SELECT * FROM t4 WHERE t4 MATCH 'hello';"
Test percentile & scanstatus
sqlite3-tool compile-options              -- everything, one per line
sqlite3-tool compile-options WORKER       -- filter

-- or straight from SQL:
sqlite3 :memory: "SELECT sqlite_compileoption_used('ENABLE_PERCENTILE');"   -- 1
sqlite3 :memory: "SELECT sqlite_compileoption_used('SECURE_DELETE');"       -- 0  (as it should be)

-- Do NOT test ENABLE_JSON1 or ENABLE_DESERIALIZE: those macros no longer
-- exist, so they always report 0 even though the features are present.
sqlite3 :memory: "SELECT json_extract('{\"a\":1}','$.a');"                   -- 1
