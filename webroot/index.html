01

What This Module Does

Installs a standalone, max-feature sqlite3 binary to /system/bin/sqlite3. Built from source with the Android NDK. Every stable feature enabled, tuned for stability and maximum compatibility.

Overlays /system/bin/sqlite3
Does not touch libsqlite.so
Apps unaffected
Safe to uninstall
🛡
Safe by design. Only the interactive sqlite3 shell is replaced. libsqlite.so used by Android framework and all apps is untouched.
🆕
New in v3.53.4-r2. UPDATE / DELETE … LIMIT really works now. Double-quoted strings are accepted again, so app databases with old-style views and triggers can be read, written and altered. Commits use fdatasync(). sqlite3-tool backups can no longer overwrite their own source, restores go through SQLite, and write commands show SQLite's real error. sqlite3-doctor reports a check that could not run instead of passing it.
⚙
Wrapper architecture. The installed sqlite3 is a lightweight shell script. It sets busy_timeout and an mmap_size scaled to your device RAM via -cmd, then hands every argument unchanged to sqlite3.real — the actual compiled binary. Everything else comes from compile-time defaults. SQLITE3_NO_WRAPPER=1 skips the wrapper entirely.

Compile Flags

⚙ Compiler
-O2Balanced optimization. Safe and stable — no aggressive transformations that risk miscompilation on Android.
-march=armv8-aTargets the ARMv8-A baseline. Compatible with every arm64 Android device regardless of chip generation.
-fPIEPosition-Independent Executable. Required by Android for ASLR (address space layout randomization).
-pieLinker flag that pairs with -fPIE. Android 21+ refuses to run non-PIE executables.
-fuse-ld=lldLLVM's LLD linker, the NDK default. Handles --gc-sections and the 16 KB page alignment below.
-fomit-frame-pointerFrees the frame pointer register for general use. Slight speed and size gain. Safe for a CLI tool.
-fvisibility=hiddenMarks all symbols as internal by default. Reduces binary size and prevents symbol leakage.
-ffunction-sectionsPuts each function in its own ELF section so the linker can discard unused ones via --gc-sections.
-fdata-sectionsSame as above but for data objects. Works together with -ffunction-sections.
-fstack-protector-strongStack smashing protection on functions that use buffers. Stability and security without the overhead of full stack protection.
🔗 Linker
-Wl,--gc-sectionsGarbage-collects ELF sections with no references. Works with -ffunction-sections / -fdata-sections.
-Wl,--as-neededDrops libraries nothing references. Earlier builds carried a NEEDED entry for liblog.so without ever calling it; the binary now needs only libc.so and libm.so.
-Wl,--strip-allStrips all symbol and debug info from the final binary. Smaller size, nothing useful for reverse engineering.
-Wl,-O2Linker optimization level 2: merges duplicate strings for a slightly smaller binary.
-Wl,--build-id=noneRemoves the GNU build-ID note section. Shaves bytes with no practical downside for a Magisk module.
-Wl,-z,relro -Wl,-z,nowFull RELRO: relocations are resolved at load time and the GOT is made read-only afterwards. Standard hardening for Android executables.
-Wl,-z,max-page-size=16384Aligns segments for devices with 16 KB memory pages. Without it the binary fails to load on those devices.
-Wl,-z,common-page-size=16384Pairs with max-page-size so the segment layout is laid out for 16 KB pages as well.
-lmLinks the math library. Required by SQLite math functions. No -ldl: with extension loading omitted nothing calls dlopen().
🗄 Core
-DSQLITE_THREADSAFE=1Full mutex serialization. Multiple threads can safely share a single database connection.
-DSQLITE_USE_URI=1Enables URI filenames such as file:db?mode=ro or file:db?immutable=1, so open flags can be passed in the filename. (The shell also has -readonly for a plain read-only open.)
-DSQLITE_OMIT_LOAD_EXTENSIONDisables runtime loading of .so extension files. Reduces attack surface on Android.
-DSQLITE_DQS=3Double-quoted string literals are accepted, as in a default SQLite build, so app databases whose views or triggers use "text" can still be queried, written and altered. In your own SQL use single quotes for strings; .dbconfig dqs_dml off gives the strict behaviour for a session.
-DSQLITE_LIKE_DOESNT_MATCH_BLOBSLIKE skips BLOB columns instead of attempting string coercion. More correct behavior and a small speedup.
-DSQLITE_HAVE_ISNANUse the platform isnan() from <math.h> instead of SQLite's own fallback. Correct NaN handling on Android.
-DHAVE_MALLOC_H=1
-DHAVE_MALLOC_USABLE_SIZE=1		SQLite asks bionic for the size of an allocation with malloc_usable_size() instead of storing an 8-byte size header in front of every block. Both macros are needed.
-DHAVE_FDATASYNC=1Commits call fdatasync() instead of fsync(), skipping the extra metadata flush on every sync. SQLite only does this when told the platform's fdatasync() can be trusted, which on Linux it can.
-DHAVE_LOCALTIME_R=1Date functions with the 'localtime' modifier use the thread-safe localtime_r() instead of localtime() under a global mutex.
⚡ Performance & Memory
-DSQLITE_TEMP_STORE=2Temporary tables and indices default to RAM, but PRAGMA temp_store can still override it (=3 would force RAM even for a huge temp table).
-DSQLITE_DEFAULT_MEMSTATUS=0Disables per-allocation memory accounting. Removes overhead from every malloc/free call.
-DSQLITE_MAX_WORKER_THREADS=4Upper bound for the parallel sorter threads.
-DSQLITE_DEFAULT_WORKER_THREADS=2Two sorter threads by default — noticeably faster CREATE INDEX and large ORDER BY on a multi-core phone.
-DSQLITE_ENABLE_SORTER_REFERENCESThe sorter keeps rowid references instead of whole rows where it can, cutting memory use when sorting wide tables.
-DSQLITE_DEFAULT_CACHE_SIZE=-16000Default page cache ~16MB per connection. The wrapper does not change it.
-DSQLITE_STMTJRNL_SPILL=-1Statement journals never spill to disk — always stay in RAM.
-DSQLITE_DEFAULT_WAL_SYNCHRONOUS=1WAL-mode sync defaults to NORMAL. Faster on flash without sacrificing safety.
-DSQLITE_DEFAULT_SYNCHRONOUS=1Default journal-mode sync is NORMAL. Balance between data safety and write speed.
-DSQLITE_DEFAULT_FOREIGN_KEYS=1FK enforcement ON by default. No need to run PRAGMA foreign_keys=ON every session.
-DSQLITE_DEFAULT_MMAP_SIZE=268435456Compile-time mmap default 256MB. For the database passed on the command line the wrapper replaces it with a RAM-scaled value (64–512MB).
-DSQLITE_MAX_MMAP_SIZE=1099511627776Maximum allowed mmap window 1TB. Removes the ceiling for very large databases.
🔍 Full-Text Search
-DSQLITE_ENABLE_FTS3_PARENTHESISSwitches FTS3/FTS4 to the enhanced query syntax: AND, OR, NOT and parentheses, e.g. word1 AND (word2 OR word3). Has no effect on FTS5, which has its own syntax.
-DSQLITE_ENABLE_FTS4Full-Text Search v4. Automatically includes FTS3. Required to read Android system DBs (contacts, calendar, SMS).
-DSQLITE_ENABLE_FTS5Full-Text Search v5. Completely independent engine from FTS4. Faster ranking, BM25 scoring, prefix queries, highlight/snippet.
📍 Geospatial · 📊 Stats & Math
-DSQLITE_ENABLE_RTREER-Tree spatial indexing. Fast bounding-box queries on coordinate data.
-DSQLITE_ENABLE_GEOPOLYPolygon-based geospatial extension on top of R-Tree. Containment and overlap queries on arbitrary polygons.
-DSQLITE_ENABLE_STAT4Histogram statistics on index columns during ANALYZE. Better query planner decisions.
-DSQLITE_ENABLE_MATH_FUNCTIONSAdds sin(), cos(), sqrt(), pow(), ln(), log() (base 10), floor(), ceil(), pi() directly in SQL.
-DSQLITE_ENABLE_PERCENTILEAdds median(), percentile(), percentile_cont(), percentile_disc() aggregate functions.
-DSQLITE_ENABLE_OFFSET_SQL_FUNCEnables sqlite_offset(column) — returns byte offset of a column value in the DB file.
↻ Session · 🔬 Virtual Tables · 🔧 Developer
-DSQLITE_ENABLE_SESSIONRecord DB changes as a changeset blob, apply to another database. Enables sync workflows.
-DSQLITE_ENABLE_PREUPDATE_HOOKFires before every UPDATE/DELETE with old row values. Mandatory dependency for SESSION.
-DSQLITE_ENABLE_SNAPSHOTOpen a read transaction against a specific historical WAL snapshot — consistent multi-step reads while writers keep going.
-DSQLITE_ENABLE_RBUResumable Bulk Update: apply a large update to a live database in interruptible chunks without holding a long write lock.
-DSQLITE_ENABLE_UNLOCK_NOTIFYUnlock-notification API. Threads waiting on a locked DB are notified instead of polling.
-DSQLITE_ENABLE_DBSTAT_VTABdbstat virtual table — page-level statistics of the database file.
-DSQLITE_ENABLE_DBPAGE_VTABdbpage virtual table — raw read/write access to every page of the DB file.
-DSQLITE_ENABLE_STMTVTABsqlite_stmt virtual table — lists all open prepared statements.
-DSQLITE_ENABLE_BYTECODE_VTABbytecode virtual table — exposes VDBE bytecode of a statement as rows.
-DSQLITE_ENABLE_CARRAYcarray virtual table — bind a C array to a virtual table for SQL joins.
-DSQLITE_ENABLE_COLUMN_METADATAEnables sqlite3_column_table_name() and related APIs for column origin info.
-DSQLITE_ENABLE_NORMALIZEEnables sqlite3_normalized_sql() — replaces all literals with ? for query logging.
-DSQLITE_ENABLE_UPDATE_DELETE_LIMITAllows ORDER BY / LIMIT on UPDATE and DELETE, e.g. DELETE FROM log ORDER BY ts LIMIT 1000. SQLite only honours it when the SQL parser is generated with it, so build.sh rebuilds sqlite3.c from sqlite-src instead of using the ready-made amalgamation.
-DSQLITE_ENABLE_EXPLAIN_COMMENTSHuman-readable comments in EXPLAIN output. Makes VDBE opcode listing easier to read.
-DSQLITE_ENABLE_UNKNOWN_SQL_FUNCTIONSuppresses "no such function" in EXPLAIN mode. Plan queries with UDFs without executing them.
-DSQLITE_SOUNDEXAdds soundex() for phonetic string matching.
-DSQLITE_ENABLE_API_ARMORRuntime sanity checks on public API entry points. Catches NULL pointers, closed handles.
-DSQLITE_ENABLE_NULL_TRIMTrailing NULLs not stored in B-Tree records. Reduces row size for sparse tables.
-DSQLITE_ENABLE_STMT_SCANSTATUS opt-in, not in this buildPer-statement scan statistics for .scanstats. It adds counters to every sqlite3_step() call whether you use them or not. Build with WITH_SCANSTATUS=1 ./build.sh to get it.
💡
FTS3 / FTS4 / FTS5 are all included. FTS5 is a completely separate engine — no shared code with FTS4. FTS4 is kept because Android system databases use FTS4 tables. FTS3_PARENTHESIS belongs to the FTS3/FTS4 engine and only changes its query syntax.
04

Session Config

The module uses a wrapper + real binary architecture. The wrapper passes two PRAGMAs via -cmd on every start — no .sqliterc dependency, no $HOME issues. Everything else is a compile-time default, so it applies to every connection, including ones made with .open.

Set by the wrapper

busy_timeout5000Wait up to 5 seconds on a locked DB instead of failing immediately.
mmap_sizeadaptive64MB <3GB RAM · 128MB 3–6GB · 256MB 6–12GB · 512MB >12GB. Read from /proc/meminfo at startup.

Compiled in — always active

cache_size-16000~16MB page cache per connection.
temp_storememoryTemp tables stay in RAM. PRAGMA temp_store reports 0 (default) — the default itself is memory.
synchronousNORMALFor both rollback-journal and WAL mode.
foreign_keysONFK constraints are enforced.

Not changed from SQLite's defaults: wal_autocheckpoint (1000 pages), recursive_triggers (OFF), journal_mode (whatever the file already uses). The commented-out options in the full config file below cover those.

Full config file — manual use

Deployed to /data/local/.sqliterc-full. Use when you need the commented-out dangerous PRAGMAs for personal databases.

Load full config on a specific DB
sqlite3 -init /data/local/.sqliterc-full /data/local/tmp/mydb.db
⚠
.open resets the wrapper settings. .open inside the shell creates a new connection with busy_timeout back to 0 and mmap_size back to the compiled 256MB. Pass the database on the command line when those matter — for example on a live system database.

Basic Usage

Root is needed for app and system databases and for /data/local/tmp, which the examples below use. Type su first and run the commands inside that root shell. :memory: databases and files in your own Termux home work without root.

⚠
Careful with su -c. su -c joins all its arguments into one string and runs it through /system/bin/sh again, so the quotes around your SQL are lost and ( becomes shell syntax: /system/bin/sh: syntax error: unexpected '('. The same happens with an alias such as alias sqlite3='su -c sqlite3'. Either pass the whole command as one quoted string, or feed the SQL through standard input, which works in every case:
SQL via stdin — works with su -c too
sqlite3 /data/local/tmp/mydb.db <<'EOF'
SELECT sqlite_version();
EOF
One quoted string for su -c
su -c 'sqlite3 /data/local/tmp/mydb.db ".tables"'
Open shell (in-memory)
sqlite3
Open or create a DB file
sqlite3 /data/local/tmp/mydb.db
Open read-only (URI)
sqlite3 "file:/data/local/tmp/mydb.db?mode=ro"
Dot commands (CLI only — not SQL)
.open /data/local/tmp/other.db    -- switch to another DB without restarting
.tables                            -- list all tables
.schema users                      -- show CREATE statement for a table
.headers on                        -- show column names in output
.mode column                       -- aligned column output
.mode box                          -- box-drawing table output
.output /data/local/tmp/out.txt    -- redirect output to file
.output stdout                     -- restore output to screen
.read /data/local/tmp/script.sql   -- execute a SQL file
.dump                              -- dump entire DB as SQL
.quit                              -- exit the shell
Basic SQL
CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT, age INTEGER);
INSERT INTO users VALUES (1, 'Alice', 30);
SELECT * FROM users WHERE age > 20;
UPDATE / DELETE with LIMIT
-- keep only the newest 1000 rows of a log table
DELETE FROM log ORDER BY ts DESC LIMIT -1 OFFSET 1000;

-- touch just one row
UPDATE users SET age = age + 1 WHERE name = 'Alice' LIMIT 1;
WAL mode (recommended for personal DBs)
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA cache_size = -20000;
System databases
sqlite3 /data/data/com.android.providers.contacts/databases/contacts2.db
sqlite3 /data/data/com.android.providers.telephony/databases/mmssms.db

sqldiff — Compare Databases

Compares two SQLite databases and outputs the SQL needed to transform one into the other. Useful for auditing changes, migrations and backups.

Basic usage
# SQL that transforms db1 into db2
sqldiff db1.db db2.db

# Only schema differences
sqldiff --schema db1.db db2.db

# Only one table
sqldiff --table users db1.db db2.db

# Per-table counts, no SQL
sqldiff --summary db1.db db2.db

# Include FTS3/4/5 and R-Tree tables
sqldiff --vtab db1.db db2.db
Wrap in transaction
sqldiff --transaction db1.db db2.db | sqlite3 db1.db
💡
Backup workflow. Make a backup with sqlite3-tool backup, modify the original, then use sqldiff to see exactly what changed.

sqlite3-doctor — Full Diagnostics

Runs a comprehensive health check on any SQLite database file: integrity, WAL state, fragmentation, foreign keys and table stats. If a check cannot run — the database is locked or unreadable — it shows SQLite's error and counts it as a problem instead of reporting a pass. Exit code is 0 when healthy, 1 otherwise.

Usage
sqlite3-doctor /data/local/tmp/mydb.db
sqlite3-doctor --quick /data/data/com.example/databases/app.db   # skip integrity_check and row counts
sqlite3-doctor --full  /sdcard/big.db                            # count rows even above 256 MB

sqlite3-tool — Helper Commands

16 ready-to-use commands for common maintenance, no SQL needed. Run them as sqlite3-tool <command> …. Every command waits up to 5 seconds on a busy database instead of failing with database is locked, refuses files that are not SQLite databases, and write commands show SQLite's own error message when something goes wrong.

info <db>Quick summary: journal mode, page size, encoding, WAL size, table count.
tables <db>All tables with row counts.
indexes <db>All indexes and the table each belongs to.
schema <db> [table]CREATE statements, ending in ;. For one table, its indexes and triggers too.
size <db>File size, page size, page and freelist counts, WAL size.
biggest <db> [n]The n largest tables and indexes on disk (default 10), via dbstat.
integrity <db>PRAGMA integrity_check.
vacuum <db>Defragment and shrink the file.
analyze <db>Refresh the query planner statistics.
optimize <db>PRAGMA optimize.
wal-checkpoint <db>Merge the WAL into the database. Says how many frames were merged, and warns when another connection kept it from finishing.
backup <db> <file or dir>Online backup, checked with integrity_check before it replaces anything. A directory gets a file with the same name.
restore <backup> <db>Writes a backup back into a database through SQLite.
doctor <db>Runs sqlite3-doctor.
compile-options [filter]How this sqlite3 was built, e.g. compile-options FTS.
versionTool, SQLite and binary versions.
Practical examples
# Check integrity, then defragment and shrink
sqlite3-tool integrity /data/local/tmp/mydb.db
sqlite3-tool vacuum    /data/local/tmp/mydb.db

# Backup before modifying an app database
sqlite3-tool backup /data/data/com.example/databases/app.db /sdcard/app_backup.db

# Backup into a folder, keeps the name (app.db)
sqlite3-tool backup /data/data/com.example/databases/app.db /sdcard/

# Put it back (stop the app first: am force-stop com.example)
sqlite3-tool restore /sdcard/app_backup.db /data/data/com.example/databases/app.db

# Quick overview / tables with row counts
sqlite3-tool info   /data/local/tmp/mydb.db
sqlite3-tool tables /data/local/tmp/mydb.db
🛡
Backup and restore go through SQLite, not cp. backup uses the online backup API (.backup): safe on a live database and it needs no write access to the source. It writes to a temporary file, checks it with integrity_check, and only then replaces the destination — a failed backup leaves your previous copy untouched, and giving the same file as source and destination is refused. restore uses .restore, which takes the proper locks and keeps the database file's owner and SELinux label, so the app can still open it afterwards.

Verify After Install

Version
sqlite3 --version
sqlite3.real --version    # the real binary, without the wrapper
Verify session PRAGMAs are active
-- run inside the sqlite3 shell
PRAGMA cache_size;    -- -16000  (compile-time default)
PRAGMA busy_timeout;  -- 5000    (set by the wrapper)
PRAGMA temp_store;    -- 0       (= default, which is memory in this build)
PRAGMA foreign_keys;  -- 1

-- NOTE: .open makes a NEW connection and resets busy_timeout and
-- mmap_size back to the compiled defaults. Pass the database on the
-- command line if you want the wrapper settings to apply to it.
Verify mmap (needs a real DB file)
sqlite3 /data/local/tmp/test.db
PRAGMA mmap_size;    -- 67108864 · 134217728 · 268435456 · 536870912, by RAM
.quit
rm -f /data/local/tmp/test.db
Test FTS5
sqlite3 :memory: <<'EOF'
CREATE VIRTUAL TABLE t USING fts5(c);
INSERT INTO t VALUES('hello world');

EOF
# expected: hello world

INSERT INTO t4 VALUES('hello world');
